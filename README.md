# 2026 WINK Spring Boot 4주 챌린지

WINK 백엔드 파트에서 진행하는 4주짜리 실습형 챌린지입니다. 강의를 듣고 끝나는 스터디가 아니라, 매주 주어진 주제를 직접 구현하고 PR로 제출하면서 **4주 동안 하나의 서버를 완성**하는 방식으로 진행됩니다.

Java나 서버 개발이 처음이어도 괜찮습니다. 매주 자료는 처음 접하는 사람 기준으로 준비되어 있습니다.

## 진행 방식

```
세미나 → 과제 수행 → PR 제출 → 다음 세미나에서 리뷰 → 다음 세미나
```

세미나 시간은 개념을 처음 배우는 자리가 아니라, **각자 만들어 온 걸 공유하고 막힌 지점을 푸는 자리**입니다. 자료는 혼자 읽고 실습까지 끝낼 수 있게 작성되어 있으니, 세미나 전까지 반드시 자료를 읽고 과제를 완료한 뒤 참여해주세요.

| 시점 | 하는 일 |
| --- | --- |
| 세미나 직후 ~ 다음 세미나 전날 | 자료를 읽고, 실습을 완성하고, 과제 PR을 올립니다 |
| 다음 세미나 (매주 목요일 18:30) | ① 지난 과제 리뷰 → ② 부원 발표 → ③ 질문 타임 → ④ 이번 주 자료 설명 |

## 기술 스택

Java 17 · Spring Boot 3.x · Spring Data JPA · MySQL · AWS (EC2 · RDS)

## 4주 동안 만드는 것

4주 내내 하나의 **커뮤니티 게시판 서버**를 이어서 만듭니다. 매주 새 예제를 만들지 않고, 지난주에 만든 코드가 다음 주의 재료가 됩니다.

```
1주차:  [Scanner]  → PostService → [System.out]
2주차:  [HTTP]     → PostService → [JSON]          ← 입출력만 교체
3주차:  [HTTP]     → PostService → [MySQL]          ← 저장소만 교체
4주차:  [인터넷]    → PostService → [RDS]           ← 실행 위치만 교체
```

4주 후에는 `https://{내도메인}`으로 접속 가능한, 누구나 쓸 수 있는 본인의 API 서버를 갖게 됩니다.

## 레포 구조

```
2026-Spring-Challenge/

├── .gitignore
├── week1/
│   ├── {이름1}/
│   ├── {이름2}/
│   └── ...
├── week2/
│   ├── {이름1}/
│   └── ...
├── week3/
│   └── ...
└── week4/
    └── ...
```

`week{n}/{본인 이름}/` 경로 아래에 그 주차 프로젝트를 둡니다. 주차마다 본인 이름 폴더를 새로 만들어주세요.

## 과제 제출 방법

```bash
git clone https://github.com/KMU-WINK/2026-Spring-Challenge.git
cd 2026-Spring-Challenge

git checkout -b feature/1주차-{본인이름}
mkdir -p week1/{본인이름}
# week1/{본인이름}/ 안에서 프로젝트 작업

git add .
git commit -m "feat: 1주차 콘솔 게시판 구현"
git push origin feature/1주차-{본인이름}
```

이후 GitHub에서 `Main`을 대상으로 PR을 생성하고, 아래 [PR 템플릿](#pr-템플릿)을 채워 제출합니다. 제출한 PR은 리뷰 후 `Main`에 머지됩니다.

주차가 바뀌면 최신 `Main`을 받아서 새 브랜치를 만들고, `week2/{본인이름}/`처럼 새 폴더에서 시작하되 **직전 주차 폴더의 코드를 복사해와서 이어서 작업**해주세요.

```bash
git checkout main
git pull origin main

git checkout -b feature/2주차-{본인이름}
mkdir -p week2
cp -r week1/{본인이름} week2/{본인이름}
```

## PR 템플릿

PR 본문에 아래 내용을 채워 제출해주세요. **「🙋 질문」 칸을 비워두지 마세요.** 여기 적힌 질문을 모아 다음 세미나의 과제 리뷰를 구성합니다.

```markdown
## 구현한 것
- [ ] 필수 1.
- [ ] 필수 2.
- [ ] 심화 (푼 것만 체크)

## 실행 화면
(캡처 첨부)

## 막혔던 부분
- 어디서:
- 어떻게 해결했는지 (or 못 했는지):

## 🙋 질문 (세미나에서 다뤄주세요)
-

## 키워드 과제
- 링크:

## 발표 신청
- 유형: (코드 리뷰형 / 개념 정리형 / 삽질 공유형)
- 주제:
```

## 발표

매주 세미나 시간에 참여자 전원이 **한 명당 5분씩** 발표합니다. 아래 세 가지 유형 중 하나를 골라 준비하면 됩니다.

- **코드 리뷰형** — 심화 과제 중 하나를 어떻게 풀었는지 코드를 보여주며 설명
- **개념 정리형** — 키워드 과제 중 하나를 본인 말로 설명
- **삽질 공유형** — 어디서 막혔고 무엇을 시도했는지 공유 (**끝내지 못했어도 발표 가능**)

발표 유형과 주제는 PR의 「발표 신청」 칸에 적어 제출해주세요. 잘한 사람이 뽐내는 자리가 아니라, 서로 다르게 푼 방식과 막힌 지점을 나누는 자리입니다. **막힌 채로 공유하는 것도 좋은 발표입니다.**

## AI 사용 가이드

ChatGPT, Claude, Copilot 등 AI 사용을 금지하지 않습니다. 다만 이 챌린지의 목표는 AI가 코드를 만드는 것이 아니라 **본인이 코드를 이해하고 설명할 수 있게 되는 것**입니다.

**이렇게 사용해도 됩니다**
- 에러 메시지의 의미 물어보기
- 이해되지 않는 개념 설명 요청하기
- 작성한 코드의 문제점·개선점 물어보기
- 막힌 문제의 힌트나 접근 방향 요청하기
- 개발 환경 문제 해결하기

**여기까지는 주의해서 사용하세요**
AI에게 구현 방법이나 예시 코드를 받을 수는 있습니다. 다만 그대로 복사하지 말고, 코드를 읽고 이해한 뒤 AI 답변을 닫고 본인이 다시 작성해보세요. **제출한 코드는 본인이 한 줄씩 설명할 수 있어야 합니다.**

**이렇게 사용하면 안 됩니다**
- 과제 전체를 AI에게 구현해달라고 요청하기
- AI가 만든 완성 코드를 그대로 복사해서 제출하기
- 키워드 과제를 AI 답변 그대로 제출하기
- 이해하지 못한 코드를 제출하기

> **판단 기준: AI가 없어진 상태에서도 내가 제출한 코드를 설명하고 다시 만들 수 있는가?**
> YES라면 AI를 잘 사용한 것이고, NO라면 AI에게 과제를 맡긴 것입니다.
